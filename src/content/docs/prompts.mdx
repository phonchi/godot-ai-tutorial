先說清楚規則，再讓 agent 改程式。每次只處理一個可以執行確認的小任務；任務越具體，越容易判斷完成與否。

## 第一次開啟專案

<AgentTask title="先讀專案，不修改" prompt={`這是我的 Godot 4.7.2 GDScript 專案。先讀 project.godot、主場景、相關腳本與專案規則。
請說明：目前遊戲如何啟動、哪些節點負責角色與計分、哪些地方還不確定。
這一輪不要修改檔案，也不要安裝外掛或更改全域設定。`} />

## 實作一個功能

<AgentTask title="加入收集功能" prompt={`先閱讀現有專案與規則。這一輪只加入收集物件：
1. 玩家碰到物件時，分數增加 1，該物件消失。
2. 同一物件只能計分一次。
3. 累積 10 分後進入勝利狀態，停止生成障礙。
沿用現有節點與訊號設計，不重寫角色移動、不新增套件。
先列修改計畫；完成後列出改動檔案、執行的檢查，以及仍需我試玩的項目。`} />

## 回報實際錯誤

<AgentTask title="用證據定位錯誤" prompt={`Godot 版本：4.7.2。請先定位原因，不要一次重寫整個場景。
操作步驟：[填入可重現步驟]
預期結果：[填入]
實際結果：[填入]
完整錯誤訊息：[貼上 Output/Debugger 原文]
最近修改：[貼上 git diff 或改動摘要]
請追蹤實際執行路徑，區分解析錯誤、節點參照、訊號連接與遊戲規則問題。`} />

## 確認修改是否完成

<AgentTask title="審查差異與完成條件" prompt={`請只讀取本次 git diff 與相關程式，逐項核對需求。
每一項請列出：對應程式位置、可確認的行為、需要實際執行才能判斷的部分。
不要因為素材檔存在就判定場景已使用它；不要因為 headless 啟動成功就判定畫面與手感正確。
這輪不要修改檔案，也不要 commit 或 push。`} />

## 將專案交給下一輪 agent

先保存 Git 版本，再記錄目前目標、完成項目、待解問題、重現步驟與相關檔案。不要把 token、帳號憑證或整份無關私人資料貼進提示詞。這些任務可在 Claude Code 或 Codex 中使用，實際工具權限依你的環境決定。
