## 學習目標

1. 建立以 `CharacterBody3D` 為根節點的玩家場景，用膠囊形狀當外觀與碰撞。
2. 寫出 3D 移動：WASD 或方向鍵在水平面移動、受重力影響、在地面時按空白鍵跳躍。
3. 讓角色模型平滑轉向移動方向。
4. 寫一個**固定偏移**跟隨玩家的攝影機：攝影機角度不隨滑鼠轉動，始終從玩家後上方看過去。
5. 處理玩家掉出場地的情況，並保留 R 重新開始。

本章對應 3D 範例的「02 controller」階段，見 [下載頁](../../downloads/)。

## 核心概念

### 3D 角色的速度分成兩部分

在 3D 平台遊戲中，`velocity` 可以拆成：

- **水平部分**（X 與 Z）：由玩家輸入決定。
- **垂直部分**（Y）：由重力與跳躍決定。

每個物理影格：在空中就讓 Y 速度被重力往下拉；在地面上按跳躍就給 Y 一個向上的速度。水平與垂直分開處理，邏輯就很清楚。

### 為什麼攝影機不當玩家的子節點

如果把 `Camera3D` 直接放在玩家底下，玩家轉向時攝影機會跟著轉，畫面會猛烈旋轉。本課程的規格是「固定跟隨」：攝影機永遠保持在玩家後上方的固定偏移，只跟著位置移動，不跟著角色轉向。所以把攝影機放在主場景中，用腳本追蹤玩家位置。

因為攝影機永遠從 +Z 方向往 -Z 方向看，按 W 讓角色往 -Z 走，在畫面上就是「往遠處走」，輸入方向與畫面方向自然一致。

## 動手操作

### 步驟 1：玩家場景

1. 新增場景，根節點 `CharacterBody3D`，命名 `Player`，加入 `player` 群組。
2. 加入 `CollisionShape3D`，`Shape` 選 `CapsuleShape3D`，半徑 `0.4`、高度 `1.8`，位置 `(0, 0.9, 0)`。
3. 加入 `Node3D`，命名 `Visual`。在它底下：
   - `MeshInstance3D`，`Mesh` 選 `CapsuleMesh`，半徑與高度同上，位置 `(0, 0.9, 0)`，材質選醒目的顏色。
   - 另一個 `MeshInstance3D` 當「鼻子」，`BoxMesh` 大小 `(0.2, 0.2, 0.3)`，位置 `(0, 1.4, -0.45)`，讓你看得出角色面向哪裡（-Z 方向）。
4. 存成 `player.tscn`。

`Visual` 這一層是重點：之後只旋轉 `Visual`，不旋轉整個物理體，碰撞與移動方向就不會被轉向影響。

### 步驟 2：移動、重力與跳躍

```gdscript
# 示範概念：第三人稱 3D 角色控制
extends CharacterBody3D

@export var speed := 5.0
@export var jump_velocity := 5.5
@export var turn_speed := 10.0

var gravity: float = ProjectSettings.get_setting("physics/3d/default_gravity")

@onready var visual: Node3D = $Visual

func _physics_process(delta: float) -> void:
	# 垂直：重力與跳躍
	if not is_on_floor():
		velocity.y -= gravity * delta
	if Input.is_action_just_pressed("jump") and is_on_floor():
		velocity.y = jump_velocity

	# 水平：依輸入移動
	var input_dir := Input.get_vector("move_left", "move_right", "move_up", "move_down")
	var direction := Vector3(input_dir.x, 0.0, input_dir.y)
	if direction != Vector3.ZERO:
		velocity.x = direction.x * speed
		velocity.z = direction.z * speed
		var target_angle := atan2(-direction.x, -direction.z)
		visual.rotation.y = lerp_angle(visual.rotation.y, target_angle, turn_speed * delta)
	else:
		velocity.x = move_toward(velocity.x, 0.0, speed)
		velocity.z = move_toward(velocity.z, 0.0, speed)

	move_and_slide()
```

### 步驟 3：放進主場景

1. 打開第 14 章的 `main.tscn`，把 `player.tscn` 拖進來，位置設成 `PlayerSpawn` 標記的位置。
2. 刪除或保留第 14 章的固定 `Camera3D`，下一步會為它加腳本。

### 步驟 4：固定跟隨攝影機

選取主場景中的 `Camera3D`，命名 `FollowCamera`，附加腳本：

```gdscript
# 示範概念：固定偏移、平滑跟隨的攝影機
extends Camera3D

@export var target: Node3D
@export var follow_offset := Vector3(0.0, 6.0, 8.0)
@export var follow_speed := 6.0

func _ready() -> void:
	if target:
		global_position = target.global_position + follow_offset

func _physics_process(delta: float) -> void:
	if target == null:
		return
	var desired := target.global_position + follow_offset
	var weight := 1.0 - exp(-follow_speed * delta)
	global_position = global_position.lerp(desired, weight)
	look_at(target.global_position + Vector3(0.0, 1.0, 0.0), Vector3.UP)
```

存檔後，在檢查器的 `Target` 欄位按「指派」選擇 `Player` 節點。執行遊戲，攝影機會在玩家後上方跟著移動。

### 步驟 5：掉出場地與重開

在主場景腳本中：

```gdscript
# 示範概念：掉落重設與 R 重開（主場景）
extends Node3D

@onready var player: CharacterBody3D = $Player
@onready var spawn: Marker3D = $PlayerSpawn

func _physics_process(_delta: float) -> void:
	if player.global_position.y < -10.0:
		player.global_position = spawn.global_position
		player.velocity = Vector3.ZERO

func _unhandled_input(event: InputEvent) -> void:
	if event.is_action_pressed("restart"):
		get_tree().reload_current_scene()
```

## 程式碼解說

- `ProjectSettings.get_setting("physics/3d/default_gravity")`：讀取專案設定中的重力值（預設約 9.8），讓所有物體一致。較新的 4.x 版本也可以用 `get_gravity()` 取得考慮重力區域後的重力向量；使用前請確認你的版本有提供。
- `is_on_floor()`：上一次 `move_and_slide()` 後是否站在地面上。它依賴 `up_direction`（預設向上）判斷什麼是地面。
- `Input.is_action_just_pressed("jump")`：只在按下的那一影格為真，避免按住空白鍵時連續跳躍。
- `Input.get_vector(..., "move_up", "move_down")`：把 W 對應成負 Y，因此轉成 3D 時 `input_dir.y` 直接當 Z 用，W 就是 -Z（往前）。
- `atan2(-direction.x, -direction.z)`：算出讓「面向 -Z 的模型」轉向移動方向所需的 Y 軸角度。
- `lerp_angle`：在兩個角度間插值，會選最短的旋轉方向，不會從 179 度繞一大圈轉到 -179 度。
- `1.0 - exp(-follow_speed * delta)`：讓平滑跟隨的速度與影格率無關。直接寫 `lerp(a, b, 0.1)` 在高更新率螢幕上會跟得比較快。
- `look_at(目標, Vector3.UP)`：讓攝影機的 -Z 方向對準目標。對準玩家上方 1 單位（大約胸口），構圖比對準腳底好。
- `@export var target: Node3D`：Godot 4 可以直接匯出節點型別，在檢查器中指派，比寫死路徑更有彈性。

## 練習

1. 把 `follow_offset` 改成 `(0, 10, 4)` 做出接近俯視的視角，再改成 `(0, 3, 6)` 做出低角度，比較哪種最適合你的場地。
2. 讓攝影機只在 X 與 Z 方向平滑跟隨，Y 方向更慢，減少跳躍時的畫面晃動。
3. 加入衝刺：按住 Shift 時速度變為 1.6 倍（需要新增輸入動作 `sprint`）。

## 常見錯誤與限制

- **角色一直往下掉穿過地板**：地板沒有碰撞形狀，或玩家的碰撞形狀位置不對（整個膠囊在地下）。
- **按跳沒反應**：`jump` 動作沒有綁定空白鍵，或 `is_on_floor()` 永遠是 false（例如碰撞形狀底部懸空）。開啟「顯示碰撞形狀」檢查。
- **方向相反**：記得 3D 的前方是 -Z。若攝影機放在 -Z 那側看過來，輸入方向就會顛倒。
- **攝影機抖動**：攝影機在 `_process`、玩家在 `_physics_process` 時，兩者更新頻率不同可能造成抖動。本章把兩者都放在物理影格；若仍有抖動，可研究專案設定中的物理插值（physics interpolation）選項，3D 物理插值是在 4.x 較新的版本才提供，請先確認版本。
- **`Target` 沒有指派**：攝影機腳本會直接返回，畫面停在原地。
- **角色卡在牆角或平台邊緣**：膠囊形狀通常比方塊好；也可以調整 `CharacterBody3D` 的 `Floor Max Angle` 與 `Safe Margin`。
