## 學習目標

1. 用 `AnimatableBody3D` 做出來回移動的平台，並理解為什麼站在上面的角色會被「載著走」。
2. 用 `Area3D` 製作發光寶珠：上下漂浮、自轉，被收集時放大淡出。
3. 建立石拱門：拱門上 5 盞燈對應 5 顆寶珠，收滿後門用 `Tween` 降下。
4. 把「勝利」放在門**後方**的偵測區，玩家必須真的穿過拱門才算過關。
5. 掉下島嶼時回到起點，並體會 2D 與 3D 的遊戲邏輯幾乎相同。

本章對應 3D 範例的「03 platforms」階段，見 [下載頁](../../downloads/)。

## 核心概念

### 2D 到 3D 的對應

| 2D | 3D | 用途 |
| --- | --- | --- |
| `Area2D` | `Area3D` | 偵測進入，不阻擋 |
| `CharacterBody2D` | `CharacterBody3D` | 玩家角色 |
| `StaticBody2D` | `StaticBody3D` | 不會動的島嶼、拱門 |
| `AnimatableBody2D` | `AnimatableBody3D` | 由程式或動畫移動、會推動角色的物體 |
| `CPUParticles2D` | `CPUParticles3D` | 收集時的粒子爆散 |

收集、計數、勝負判斷的程式幾乎可以從 2D 篇照搬，差別只在型別與 `Vector3`。

### 移動平台為什麼要用 AnimatableBody3D

如果用 `StaticBody3D` 然後每格改它的 `position`，平台會「瞬移」，站在上面的角色不會跟著走，甚至會穿過去。`AnimatableBody3D` 是專門給「由你移動、但要能推動別人」的物體：

- 預設的 `Sync to Physics` 為開啟，物理引擎會把每次移動當成有速度的運動。
- 在 `_physics_process` 中移動平台，站在上面的 `CharacterBody3D` 呼叫 `move_and_slide()` 時，會自動加上平台的移動，**不需要**自己把平台位移加到玩家身上。

平台用 `0.5 - 0.5 * cos(phase * TAU)` 來回移動：在兩端會減速、停頓一下再回頭，玩家比較好掌握起跳時機。

### 鎖定的拱門


拱門有兩種狀態：鎖定時門板擋住入口，開啟後門板沉入地面。程式只需要一個 `gate_open` 布林值，再加上兩個規則：

- 收集到第 5 顆寶珠時呼叫 `open_gate()`。
- 門後的偵測區被進入時呼叫 `try_exit()`；寶珠不足就回傳 `false`。

門板本身有碰撞，所以鎖定時玩家根本進不了門後；`try_exit()` 再檢查一次分數，是為了讓規則在測試中也成立。

## 動手操作

### 步驟 1：移動平台

1. 在 `Main` 底下加入 `AnimatableBody3D`，命名 `Platform1`，位置放在兩座島之間的空隙，高度和島頂相同，例如 `(3.5, 1.1, -8.5)`。
2. 底下加入 `MeshInstance3D`（`BoxMesh` 大小 `(3, 0.4, 3)`，位置 `(0, -0.2, 0)`，淺石色）與同尺寸的 `CollisionShape3D`。
3. 附加腳本 `res://scripts/moving_platform.gd`：

```gdscript
# 示範概念：在物理影格中來回移動的平台
extends AnimatableBody3D

@export var travel := Vector3(0, 0, -4)
@export var cycle_time := 10.0

var origin := Vector3.ZERO
var phase := 0.0

func _ready() -> void:
	origin = position

func _physics_process(delta: float) -> void:
	phase += delta / cycle_time
	var weight := 0.5 - 0.5 * cos(phase * TAU)
	position = origin + travel * weight
```

平台頂面至少 3 × 3 公尺，10 秒走完來回 8 公尺。因為用餘弦曲線起步與減速，最快的瞬間約每秒 1.26 公尺，初學者比較容易站穩。

### 步驟 2：寶珠場景

1. 新增場景，根節點 `Area3D`，命名 `Orb`。
2. 加入 `MeshInstance3D`，`SphereMesh` 半徑 `0.38`、高度 `0.76`，`Radial Segments` 8、`Rings` 4，做出低面數的寶石感。
3. 材質勾選 `Emission`，顏色選金色，`Energy Multiplier` 約 `1.1`。配合第 14 章開啟的光暈，寶珠會微微發光。
4. 加入 `CollisionShape3D`，`SphereShape3D` 半徑 `0.8`，比外觀大一點，比較容易碰到。
5. 附加腳本 `res://scripts/orb.gd`：在 `_process` 中讓外觀自轉，並用 `sin()` 上下漂浮。只動外觀節點，碰撞範圍保持不動。

```gdscript
func pop() -> void:
	set_deferred("monitoring", false)
	var fade: StandardMaterial3D = visual.material_override
	fade.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA
	var tween := create_tween()
	tween.tween_property(visual, "scale", Vector3.ONE * 2.0, 0.2)
	tween.parallel().tween_property(fade, "albedo_color:a", 0.0, 0.2)
	tween.tween_callback(queue_free)
```

`set_deferred("monitoring", false)` 讓寶珠在下一個安全時機停止偵測，避免在碰撞回呼中直接修改物理狀態。

`visual` 是 `orb.gd` 裡指向外觀 `MeshInstance3D` 的變數（例如 `@onready var visual: MeshInstance3D = $MeshInstance3D`），完整版見本章末的對照原始碼。淡出要改材質的透明度：先把材質的 `Transparency` 設為 `Alpha`，再用 Tween 把 `albedo_color:a` 降到 0。`MeshInstance3D` 雖然也有 `transparency` 屬性，但 Compatibility 繪圖器會忽略它，寶珠只會放大後突然消失。每顆寶珠都要有自己的材質；若多顆共用同一份材質，淡出時會一起變透明。

### 步驟 3：擺放寶珠

把 5 顆寶珠放在島頂上方約 1 公尺：一顆在第一座島，一顆要靠移動平台才拿得到，一顆在最高的小島，最後一顆放在終點島的小台階上，需要再跳一次。

### 步驟 4：石拱門

1. 在終點島靠後方加入 `Node3D`，命名 `Gate`。
2. 底下加入 `StaticBody3D`：兩根石柱（`BoxMesh` `(0.7, 3.4, 0.7)`，各有碰撞）與一根橫樑。
3. 在橫樑正面放 5 個小方塊當燈，先用深色材質。
4. 加入 `AnimatableBody3D` 當門板：`BoxMesh` `(2.8, 3, 0.25)`、青綠色自發光材質，加上同尺寸碰撞。
5. 在門板**後方**約 0.9 公尺加入 `Area3D`，命名 `ExitArea`，碰撞盒 `(2.8, 3, 1)`。

### 步驟 5：主場景邏輯

在 `main.gd` 中，把每顆寶珠的 `body_entered` 接到 `collect_item()`，把 `ExitArea` 的 `body_entered` 接到 `try_exit()`：

```gdscript
func collect_item(orb: Area3D) -> void:
	if not is_playing() or not orbs.has(orb):
		return
	orbs.erase(orb)
	orb.pop()
	lamps[score].material_override = lamp_material
	score += 1
	if score == TARGET:
		open_gate()
	update_hud()
```

`orbs.has(orb)` 確保同一顆寶珠不會重複計分。點亮第 `score` 盞燈用的是另一份金色發光材質 `lamp_material`（成員變數，在 `_ready()` 建立一個 `emission_enabled` 的 `StandardMaterial3D`）。不要直接借寶珠的材質：寶珠淡出時會把自己材質的透明度降到 0，共用的話燈也會跟著消失。

`is_playing()` 與 `update_hud()` 是這一章新增的兩個小函式。這個階段還沒有標題畫面，`is_playing()` 只要 `return not won`；`update_hud()` 把寶珠數與拱門狀態寫進畫面上方的 `Label`。下一章加入標題與計時時，只需要改這兩個函式的內容，`collect_item()` 不用動。

### 步驟 6：掉落回到起點

沿用上一章的掉落判斷：玩家高度低於 −10 時，回到起點、速度歸零、攝影機直接對準。這一章多了移動平台，掉下去的機會變多，這個安全網就更重要了。

## 程式碼解說

- `create_tween().set_process_mode(Tween.TWEEN_PROCESS_PHYSICS)`：讓門板在**物理影格**中移動。門板是有碰撞的 `AnimatableBody3D`，用物理影格移動，碰撞與畫面才會同步。
- `tween_property(gate, "position:y", -1.7, 1.2)`：用 1.2 秒把門板降到地面以下。`"position:y"` 只改 Y，不影響其他分量。
- `set_trans(Tween.TRANS_SINE)`：開始與結束都緩和，比等速移動更像機關。
- 收集時另外用 `CPUParticles3D` 做一次性的金色粒子爆散：`one_shot` 加上 `explosiveness = 1.0`，所有粒子同時噴出，播完就用 `finished` 訊號釋放節點。
- 勝利條件放在門後，而不是「收滿 5 顆就贏」：玩家要親自走過剛打開的門，結局更有儀式感。

## 自我檢查

- [ ] 站在移動平台上不按任何鍵，角色會被載著走，不會滑落。
- [ ] 寶珠會漂浮、自轉，碰到時放大淡出並噴出金色粒子。
- [ ] 每收集一顆，拱門上就多亮一盞燈；同一顆不會重複計分。
- [ ] 收滿 5 顆前，門板擋住入口；收滿後門板平順降下。

## 練習

1. 把第二個移動平台的 `cycle_time` 改成 4，感受速度變快後的難度差異。
2. 讓寶珠被收集時，拱門上對應的燈先放大再縮回（提示：對燈也建立一個 `Tween`）。
3. 收滿 5 顆時，讓攝影機暫時看向拱門 1 秒，再回到玩家身上。

## 常見錯誤與限制

- **平台移動但角色不跟著走**：平台用了 `StaticBody3D`，或在 `_process` 而不是 `_physics_process` 中移動。
- **角色在平台上抖動**：平台速度太快或頂面太小。先加長 `cycle_time` 讓平台變慢，並把頂面做到 3 × 3 以上。
- **寶珠收集時出現物理錯誤訊息**：在碰撞回呼中直接修改 `monitoring` 或刪除節點。改用 `set_deferred()` 與 `queue_free()`。
- **門降下了卻還擋路**：門板用 `StaticBody3D` 並直接改位置，碰撞沒有同步。改用 `AnimatableBody3D` 搭配物理影格的 Tween。
- **收滿後站在門前就贏了**：偵測區放在門板前方，要移到門後。
