## 學習目標

1. 用 `Path3D`、`Curve3D`、`PathFollow3D` 讓刺球沿著路線來回巡邏。
2. 在每個物理影格檢查刺球是否碰到玩家，碰到就送回重生點。
3. 用旗子（重生點）記住最近的安全位置，並計算掉落次數。
4. 加入標題畫面、計時器、最佳紀錄（`ConfigFile` 存到 `user://`）與音效，完成整款遊戲。
5. 了解 3D 匯出到 Web 時與 2D 的差異，並用 headless 行為測試確認規則。

完成後即為 3D 遊戲的最終版本，可與 3D 範例「04 final」階段對照，見 [下載頁](../../downloads/)，或到 [試玩頁](../../play/) 遊玩。

## 核心概念

### PathFollow3D 不會自己走

`Path3D` 存放一條曲線（`Curve3D`），`PathFollow3D` 是它的子節點，代表「曲線上的某一點」。關鍵是：**`PathFollow3D` 不會自己動**，你要每格增加它的 `progress`（沿曲線走過的距離）：

```gdscript
func _physics_process(delta: float) -> void:
	progress += speed * delta
```

- `loop` 預設為開啟，走到終點會從頭開始。若曲線的終點和起點不同，敵人會「瞬移」回起點。所以建立曲線時，把**第一個點再加一次**到最後，形成封閉的路線。
- `rotation_mode` 設為 `ROTATION_Y`，敵人只沿水平方向轉向，不會因為曲線高低而歪斜。
- 敵人的外觀與碰撞放在 `PathFollow3D` 底下，就會跟著移動。

在編輯器中，選取 `Path3D` 後可以直接在 3D 視窗點擊加點，畫出路線，很直觀。

### 重生點：掉落不必整局重來

<LessonDiagram kind="respawn" />

前兩章掉下去都會回到起點。關卡變長以後，這會很挫折。做法是用一個 `respawn_point` 變數記住「最近的安全位置」：

- 碰到旗子：把 `respawn_point` 更新成旗子的位置，旗子換成薄荷綠，噴出粒子並播放音效。
- 掉到 −10 以下或碰到刺球：呼叫 `respawn_player()`，把玩家放回 `respawn_point`、速度歸零、攝影機直接對準，掉落次數加 1。

### 為什麼每格檢查碰撞

`Area3D` 的 `body_entered` 只在「進入那一瞬間」觸發一次。刺球是會移動的，如果玩家剛好站在刺球的路線上，用訊號容易漏判。改成在主場景的 `_physics_process` 中逐一檢查 `patrol.hitbox.overlaps_body(player)`，規則更可靠。2D 篇的敵人也是用同樣的思路。

## 動手操作

### 步驟 1：巡邏路線

1. 在有寶珠的那座中段島上，加入 `Path3D`，命名 `PatrolPath1`。
2. 選取它，在 3D 視窗上方工具列選「新增點」，沿著島面點出 4 個點圍成長方形，最後再點回第一個點附近，或在檢查器中把第一個點的座標複製到最後一點。
3. 在 `PatrolPath1` 底下加入 `PathFollow3D`，`Rotation Mode` 選 `Y`。

### 步驟 2：刺球

1. 在 `PathFollow3D` 底下加入 `Area3D`，命名 `Hitbox`，位置 `(0, 0.55, 0)`。
2. `Hitbox` 底下加入深紅色 `SphereMesh`（半徑 0.5）與 `SphereShape3D`（半徑 0.55）。
3. 再加 8 根 `CylinderMesh` 當尖刺：`Top Radius` 設 0，就變成圓錐，沿著球的一圈排列。
4. 對 `PathFollow3D` 附加腳本，每格增加 `progress`，並讓 `Hitbox` 繞 X 軸旋轉，看起來像在滾動。

### 步驟 3：旗子

1. 在中段島與終點島入口各放一根旗子：`Area3D` 底下有細長的旗桿方塊與一塊灰色旗面，旗面命名 `Cloth`。
2. 碰撞盒 `(1.4, 2.2, 1.4)`，比旗子大一些，路過就會觸發。
3. 旗子不要放在刺球的路線上，否則玩家一重生就又被撞到。

### 步驟 4：主場景邏輯

```gdscript
func _physics_process(delta: float) -> void:
	update_camera(delta)
	if player.global_position.y < FALL_LIMIT:
		respawn_player()
	for patrol in patrols:
		if patrol.hitbox.overlaps_body(player):
			respawn_player()
			break

func activate_checkpoint(flag: Area3D) -> void:
	var point := flag.position + Vector3(0, 0.75, 0)
	if respawn_point.is_equal_approx(point):
		return
	respawn_point = point
	var cloth: MeshInstance3D = flag.get_node("Cloth")
	cloth.material_override = material(MINT)
```

`is_equal_approx()` 用來比較浮點數向量；同一面旗子重複碰到時直接返回，不會一直播放音效。

`material(MINT)` 是回傳薄荷色 `StandardMaterial3D` 的小函式，`MINT` 是顏色常數，都要在 `main.gd` 自行宣告；完整版見本章末的對照原始碼。`patrols` 是存放所有 `PathFollow3D` 的陣列。

下載版還在重生後給 0.5 秒保護時間（`respawn_grace`），期間不判定刺球接觸。傳送後的第一個物理影格，重疊資料可能還沒更新，沒有這段保護就可能連續重生兩次。

### 步驟 5：標題、計時與最佳紀錄

沿用第 10、11 章 2D 篇的做法：

- 狀態有 `TITLE`、`PLAYING`、`WON` 三種。標題畫面按 Enter 或手把 Start 開始（`start` 動作在第 14 章已經建立）；按 R 重新開始時，用 `static var skip_title` 略過標題直接開始。
- 只有 `PLAYING` 時累加 `elapsed`，畫面右上顯示時間。
- 獲勝時若比最佳紀錄快，就用 `ConfigFile` 存到 `user://best.cfg`。讀取失敗（第一次玩）時回傳 −1，代表沒有紀錄。
- 音效有收集、跳躍、開門、旗子、重生、勝利六種，headless 執行時跳過播放。

## 程式碼解說

- `curve.add_point(route[0])`：把起點再加一次，讓路線封閉，`loop` 時不會跳回起點。
- `hitbox.rotate_x(-speed * delta / 0.5)`：滾動角度 = 移動距離 ÷ 半徑。球半徑 0.5，這樣轉速和移動速度一致，看起來不會「打滑」。
- `respawn_player()` 裡呼叫 `snap_camera()`：重生是瞬移，攝影機也要瞬移，否則畫面會從深淵慢慢追上來，讓玩家看不清楚。
- `falls` 只是計數，不會讓遊戲失敗。3D 版刻意不設生命數，讓初學者能專心體驗跳躍與探索；你可以在練習中自行加上。

## 3D 匯出到 Web：和 2D 不同的地方

匯出流程與第 13 章相同（Web 預設、關閉執行緒支援、用 HTTP 伺服器測試），這裡只說明 3D 要多注意的地方：

| 項目 | 2D | 3D |
| --- | --- | --- |
| GPU 負擔 | 很輕 | 陰影、霧、光暈都要額外繪製 |
| 陰影 | 通常沒有 | 只讓一個方向光開陰影；2 分割、最大距離 45 |
| 粒子 | `CPUParticles2D` 很便宜 | `CPUParticles3D` 每顆粒子都是網格，數量要少 |
| 單執行緒 | 幾乎沒有影響 | 物理、粒子、腳本共用同一條執行緒，越簡單越順 |
| 存檔 | `user://` 存在瀏覽器的 IndexedDB | 同左；清除網站資料就會消失 |

匯出前先在專案資料夾執行行為測試，確認規則沒有被改壞：

```bash
godot --headless --path . --script res://tests/behavior.gd
```

看到 `BEHAVIOR CHECKS: PASS` 再匯出。匯出後在瀏覽器完整玩一局，並打開開發者工具的主控台確認沒有錯誤；若畫面不順，依序嘗試關閉陰影、降低 3D 繪製比例（`get_viewport().scaling_3d_scale`）。

## 自我檢查

- [ ] 刺球沿著封閉路線持續滾動，不會跳回起點，滾動方向和移動方向一致。
- [ ] 碰到刺球會回到最近的重生點，掉落次數加 1。
- [ ] 碰到旗子時旗面變成薄荷綠；之後掉下去會回到這面旗子，而不是起點。
- [ ] 標題畫面按 Enter 開始；按 R 重新開始時直接進入遊戲。
- [ ] 獲勝畫面顯示時間與最佳紀錄，重新開始後最佳紀錄仍在。
- [ ] `res://tests/behavior.gd` 顯示 `BEHAVIOR CHECKS: PASS`，Web 版主控台沒有錯誤。

## 練習

1. 讓刺球在路線轉角停頓 0.5 秒（提示：記錄上一格的方向，方向改變時暫停增加 `progress`）。
2. 加入生命數：掉落 5 次就顯示「GAME OVER」，並在 HUD 用寶珠圖示表示剩餘生命。
3. 匯出到 Web 後，分別在開啟與關閉陰影的情況下記錄 FPS，填成表格比較。

## 常見錯誤與限制

- **刺球不動**：忘了在 `_physics_process` 增加 `progress`，或 `PathFollow3D` 不是 `Path3D` 的子節點。
- **刺球走到終點瞬移回起點**：曲線沒有封閉，把第一個點再加到最後。
- **刺球歪斜或翻倒**：`rotation_mode` 不是 `Y`，曲線有高低時整個節點會傾斜。
- **重生後立刻又被撞**：旗子放在巡邏路線上，或重生點離路線太近。
- **最佳紀錄在 Web 版消失**：瀏覽器的無痕模式或清除網站資料會清空 IndexedDB；程式要在讀取失敗時仍能正常遊玩。
- **Web 版很卡**：3D 陰影與粒子數量是主要原因，先降低這兩項再找其他問題。
