# Enhancement brief: games + site (v1, 2026-10-13)

Purpose: self-contained design draft for cross-model critique (GPT-6 via Codex, Fable). Readers: AI reviewers and the implementing agent.

## Project
- Traditional-Chinese student-facing Godot teaching site (Astro 7 + Starlight), base `/godot-ai-tutorial/`, GitHub Pages, no backend.
- Audience: programmers new to Godot, learning together with Claude Code / Codex agents.
- Godot 4.7.2, GDScript, **Compatibility renderer**, **single-thread Web export**, viewport 960×600, `canvas_items` stretch.
- All game code is generated by `scripts/build_examples.py` (one Python file containing GDScript templates as strings). Each checkpoint is a standalone project whose `main.tscn` has only a root node; everything is built in `_ready()` in code. Lessons embed real functions from checkpoints via `SourceExcerpt` (method-level excerpts), so **function names and sizes matter for teaching**: functions should be short, named by concept, and readable by beginners.
- Headless behavior tests (`tests/behavior.gd` in final stages) run with `godot --headless --script`; logs must contain zero ERROR/WARNING.
- Memory-constrained machine: Godot and browser runs are sequential.

## Problem
User verdict: "site too plain, games not impressive." Current screenshots: `verification/home-1440.png`, `verification/game-2d-after.png` (flat grid, circles, diamonds, text HUD), `verification/game-3d-after.png` (white plane, green cubes, orange capsule, yellow spheres, text HUD).

## Locked decisions (from user)
1. Expand rules, not only visuals.
2. 2D: dash + chasing enemies; 3 waves with rising difficulty + best record. 3D: platform jumping + moving platforms + key door + smooth camera; patrol enemies + fall/hit respawn.
3. Art: 100% procedural (code drawing, shaders, particles, generated audio). No external assets.
4. Site: keep warm paper/book base (#FAF9F5 paper, #141413 ink, #984832 terracotta), add game feel: animated hero, level-map course path, badges/progress, dark mode, moderate motion (respect reduced motion).
5. Keep 18 chapters. Checkpoints: 2D 01-movement, 02-collect, 03-hazards, 04-interface, 05-final; 3D 01-world, 02-controller, 03-platforms, 04-final (9 ZIPs).
6. Input: keyboard + gamepad. Mobile: show "play on desktop" notice, no touch controls.
7. Implementation by one agent; other models critique and review.

## Verified renderer facts (Godot 4.7 stable docs, renderers page)
Compatibility supports glow, depth+height fog, SSAO, tonemapping, screen/depth texture, 2D lights. Not supported: volumetric fog, SSR, SDFGI/SSIL, particle trails, particle SDF collision. Lights with shadows: multi-pass, max 8 per mesh. Plan: use CPUParticles2D/3D (deterministic, no GPU sim risk on web), `Light2D`/`PointLight2D` sparingly.

## Look spec (draft — critique this)
### 2D "Dusk Garden"
- Palette: night-teal base #12312f → #1d4b47 gradient, terracotta #d8693f enemies, gold #f2c14e gems, cream #faf3e0 player/UI, mint #7fd1b9 accent.
- Signature effects: (1) shader background with slow moving soft blobs + vignette, (2) gem idle bob + glow halo + burst particles on pickup, (3) dash afterimages + dust particles, (4) screen shake + red flash on hit, (5) wave banner sliding in with tween.

- HUD: hearts (drawn), wave pips, gem counter, timer; title screen "Press Enter / A to start"; result panel with best time.

### 3D "Floating Isles"
- Palette: sky gradient warm dawn (#f6d6b0 horizon → #7fb3c8 top), grass #8fbf6a, earth #b07a4f, stone #c9c2b3, player terracotta #d8693f, gems gold emissive, door teal #2f7e79.
- Signature effects: (1) procedural sky + distance fog + glow on gems, (2) island chunks with grass top/earth sides, (3) gem spin + bob + sparkle particles on pickup, (4) door tween rising, (5) respawn fade + puff particles.
- Silhouettes: player capsule with two eye spheres, landing squash; patrol enemy = spiky dark-red sphere rolling along path; door = stone arch with teal gate.
- Camera: third-person follow, lerp position, looks slightly ahead.

## Open questions for reviewers
1. Are the mechanics/tuning beginner-teachable within one chapter each? What numbers (speed, accel, dash distance/cooldown, chaser speed per wave, jump, coyote 0.1s, buffer 0.12s) do you suggest?
2. Which effects give the best "wow per line of code" in Compatibility + web? Anything risky (shader compile stalls on web, shadow cost, CPUParticles3D perf)?
3. Generator architecture: still one Python file with string templates, or split templates into `scripts/templates/*.gd` files with stage markers? How to express stage-gated code readably (current: `if STAGE >= 3`)?
4. Test strategy for physics-dependent behavior headless (moving platform carry, dash distance, respawn).
5. Site: which game-feel elements help learning vs distract? Anything to drop?
